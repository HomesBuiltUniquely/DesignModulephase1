1. END-TO-END FLOW
================================================================================

  User action on Lead / Dashboard
       |
       v
  Design Module Express API (backend/server.ts)
       |  e.g. POST /api/leads/:id/complete-task
       v
  notify.<function>() in backend/routes/designNotifications.ts
       |  - resolveNotificationRecipients() (MySQL users/leads)
       |  - build event_id (idempotency)
       |  - POST to NOTIFY_API_URL
       v
  NotifyProject POST /v1/design/notifications/*
       |  service/service.go → saveDesignNotification()
       |  internal/inbox/store.go → INSERT design_user_notifications
       |  internal/inbox/hub.go → WebSocket broadcast inbox_updated
       v
  Design Module frontend DesignNotificationProvider (global)
       |  WebSocket + GET inbox/counts
       |  playNotificationChime() on new notification
       v
  NotificationBell UI (dashboard only) — list, mark read, mute

  How Design Module calls NotifyProject (inside designNotifications.ts):
    - post(endpoint, body) builds event_id, resolves recipients, POST JSON to:
        NOTIFY_API_URL + endpoint
    - Body includes: project_id, lead_name, designer_id, notification_type,
      notification_action, payload, event_id, recipients[]

  Recipient fanout (resolveNotificationRecipients in same file):
    - Always: admin + deputy_general_manager
    - Plus role-specific users (finance, dqc_manager, mmt_manager, designer, PM, etc.)
    - Uses MySQL pool (notify.initPool in server.ts)

4. DESIGN MODULE BACKEND — INBOX PROXY APIs
     (Frontend → Design backend → NotifyProject inbox)
================================================================================

  Registered in: backend/routes/designNotifications.ts → registerInboxRoutes()
  Wired in:       backend/server.ts (session user id from Bearer token)

  Design Module route          | Method | Proxies to NotifyProject              | Purpose
  -----------------------------|--------|---------------------------------------|----------------------------------
  /v1/design/inbox             | GET    | GET /v1/design/inbox?user_id=         | List notifications for logged-in user
  /v1/design/inbox/counts      | GET    | GET /v1/design/inbox/counts?user_id=| Unread counts (read_at IS NULL)
  /v1/design/inbox/:id/read    | POST   | POST /v1/design/inbox/:id/read      | Mark one notification read
  /v1/design/inbox/read-all    | POST   | POST /v1/design/inbox/read-all      | Mark all read for user
  /v1/design/inbox/ws-ticket   | POST   | POST /v1/design/inbox/ws-ticket     | Get WS ticket + ws_url for live updates

  Auth:
    - Inbox routes use session Bearer token (getUserFromSession in server.ts)
    - Client user_id query/body is ignored; server uses logged-in user id
    - Proxy adds header x-external-api-key from HUB_NOTIFY_API_KEY

  Mark-read response normalization: inboxActionResponse() sets ok + success true

5B. INBOX APIs — DIRECT CALLS (bell / live notifications)
     File: app/Components/DesignNotificationProvider.tsx

  Frontend API                         | Function in provider        | Called when
  -------------------------------------|-----------------------------|------------------------------------------
  GET /v1/design/inbox?user_id=        | loadNotifications()         | On login; on WS update; on chime event;
                                       |                             | when bell opens; after mark read
  GET /v1/design/inbox/counts?user_id= | loadUnreadCount()           | Same triggers as above; drives badge #

  POST /v1/design/inbox/read-all       | handleMarkAllRead()         | User clicks "Mark all read" in bell

  Who triggers handleMarkRead / handleMarkAllRead (no fetch in these files):
    NotificationBell.tsx  → onClick notification row → handleMarkRead(item.id)
                            → "Mark all read" button → handleMarkAllRead()
    NotificationBell.tsx  → bell button → primeNotificationSound() only (no API)

  Who uses context but does NOT call inbox APIs:
    NotificationBell.tsx  → toggleMute() → localStorage only (no API)

  Window event (no HTTP — refreshes inbox + sound):
    Event: design-notification-chime (DESIGN_NOTIFICATION_CHIME_EVENT)
    Listener: DesignNotificationProvider useEffect → playNotificationChime + loadNotifications + loadUnreadCount
    Emitter:  app/lib/notificationSound.ts → signalDesignNotificationChime()

7. NOTIFYPROJECT — INBOX / BELL APIs
================================================================================

  Routed in: NotifyProject/cmd/main.go
    Paths starting with /v1/design/inbox → internal/inbox/http.go
    (takes priority over gRPC gateway for inbox)

  File roles:
    internal/inbox/http.go    REST handlers + WS endpoint
    internal/inbox/store.go   MySQL design_user_notifications CRUD
    internal/inbox/hub.go     WebSocket broadcast to connected users
    internal/inbox/tickets.go WS ticket validation
    internal/inbox/cleanup.go Delete old read/unread rows (scheduled)

  Endpoint                          | Method | Handler (http.go) | Purpose
  ----------------------------------|--------|-------------------|----------------------------------
  /v1/design/inbox                  | GET    | list()            | List user notifications
  /v1/design/inbox/counts           | GET    | counts()          | Unread total + by_type
  /v1/design/inbox/{id}             | GET    | detail()          | Single notification
  /v1/design/inbox/{id}/read        | POST   | markRead()        | Mark one read; WS reason=read
  /v1/design/inbox/read-all         | POST   | markAllRead()     | Mark all read; WS reason=read-all
  /v1/design/inbox/ws-ticket        | POST   | wsTicket()        | Issue short-lived WS ticket
  /v1/design/inbox/ws?ticket=       | GET    | ws()              | WebSocket connection
  /v1/design/inbox/events           | POST   | createEvent()     | Direct event ingest (optional)

  gRPC inbox methods (also in service/service.go, used via gateway if not caught by inbox HTTP):
    GetDesignInbox, GetDesignInboxCounts, MarkDesignNotificationRead,
    MarkAllDesignNotificationsRead, CreateDesignInboxTicket

  Auth on inbox HTTP:
    Header x-external-api-key must match NOTIFY_API_KEY env (if set)
